# Logic-Loom v0.3.2

> A security and reliability release. Every v0.3.x user should update: the
> local API that the app runs could be reached by web pages and other programs
> on the same computer.

## The local API now requires a per-launch token

The app talks to its Python sidecar over a port on `127.0.0.1`. Until now that
API had no authentication. Any program on the computer could call it, and so
could a web page, through a technique called DNS rebinding. A page that did so
could read your settings, write files through the prompt library, and change
the editor command that "Open in Editor" runs.

From this release the desktop app creates a random token at each launch. The
sidecar refuses every request that does not carry it, and every request that
does not address it by a loopback name (`127.0.0.1`, `localhost` or `[::1]`).
Nothing changes in how you use the app.

If you run the sidecar on its own for development, see
[Developer setup](../developers/index.md) for the matching environment variables.

## Hardened inputs and secrets

- Prompt-library and workflow ids can no longer name a file outside the library.
- "Open in Editor" and the node file viewer only work on files in your node
  folders, vault and the shipped node library.
- Saved API keys are never sent back to the app window. Settings show a saved key
  as dots; type over it to replace it, or empty the field to remove it.
- The editor and zsum Python commands must name a program that exists.
- Error responses no longer include server tracebacks, and malformed requests
  get a clear 4xx error instead of a server error.

## No more leftover background processes

If the app crashed or was force-quit, its sidecar could keep running in the
background. The sidecar now exits on its own whenever the app goes away, on every
platform. On Windows, closing the app also stops the helper processes the
installer's launcher starts.

Launching Logic-Loom a second time now brings the open window forward instead of
starting a second copy that would share the same settings and batches.

## Windows: the app can reach its API again

On Windows the v0.3.1 sidecar stopped right after it started, so the app could
not load its data. It now keeps serving on every platform.
